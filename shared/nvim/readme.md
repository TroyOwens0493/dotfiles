# dotfiles/shared/nvim

## Install Instructions

Follow the root [install.md](../../install.md) in the config repo. The guide
covers installing Neovim and linking `shared/nvim` to `~/.config/nvim` on both
platforms. The dependency setup restores the plugin versions from `lazy-lock.json`.
Restart Neovim after config changes.

## Code Review

CodeDiff opens a file list beside an inline diff:

| Shortcut | Comparison |
| --- | --- |
| `Space gp` | Review the current branch's open PR with `CodeDiff pr <number>` |
| `Space gv` | Create or open a guided review for the current comparison |
| `Space gc` | Latest commit: `HEAD^` against `HEAD` |
| `Space gu` | Unstaged changes: index against working files |

Press Enter to select a file, `]c` / `[c` to move between changes, and `q` to
close the diff. The colorscheme follows the selected file's language, including
while focus stays in the file list. Staged changes are hidden by default; `gs`
in the file list toggles them.

Diff colors mark changes within a line. Complete added or deleted lines keep
their `+` or `-` markers without a text background. This uses
`highlights.char_whole_line = false` in the local CodeDiff fork.
Deleted and original lines are hidden in inline diffs. Set
`diff.show_deleted_lines = true` in `lua/plugins/codediff.lua` to show them.

The fork provides AI-guided review through the local Codex CLI and its ChatGPT
sign-in. The config enables this feature and sets high reasoning effort.
Press `Space gv` or run `:CodeDiffReview start` to generate or open a guided
review. This command also loads the plugin when no CodeDiff comparison has
been opened yet.

The guide opens in a new tab. Select a stop in the sidebar to show its changes.
Use `:CodeDiffReview next` and `:CodeDiffReview prev` to move between stops.
Press `Space v` to mark the current stop as reviewed. Use
`:CodeDiffReview refresh` to generate a new guide after the comparison changes.
The original comparison stays open in its own tab.

The fork no longer provides change summary popups (`gs`), purpose popups (`gb`),
or selected-line explanations (`Space ge`). In the file list, `gs` still toggles
staged changes.

When `~/nvimPuginDev/codediff.nvim` exists, Neovim uses that local checkout.
Otherwise it uses the configured GitHub fork and branch.
Use `:Lazy restore codediff.nvim` to restore the version in `lazy-lock.json`.

`Space gp` uses the GitHub CLI (`gh`) to find the current branch's open PR
number and base branch. It uses the directory shown in Netrw or the current
file's repository, then falls back to Neovim's working directory. You can use
fzf to select a worktree and open it in Neovim without changing the shell's
directory. It opens `CodeDiff pr <number> --base <base-branch>`,
which fetches the published PR from `origin` and shows its merge-base diff.
It does not merge or change your working files, and it works with uncommitted
changes. Local commits that you have not pushed are not part of this view.
If no open PR exists, or a lookup or fetch fails, the shortcut reports an error.
